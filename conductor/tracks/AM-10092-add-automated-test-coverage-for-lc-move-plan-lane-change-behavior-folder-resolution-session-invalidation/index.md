**Problem**: bin/lc.mjs has zero automated test coverage for its move-family command (move/plan/implement/review/quality-gate/backlog/done/pulse/rerun, all sharing one code branch at command === "move" || [...].includes(command)). Two real, live bugs were found and fixed in this exact path today with no regression test written for either: (1) the folder lookup used a naive readdirSync(...).find(d => d.startsWith(trackNum + "-")) scan that silently missed every PREFIX-NNN-slug folder (the shape every affected track actually used) - fixed in ac5dd70a by switching to the canonical resolveTrackFolderFs resolver and normalizing either identifier form (bare "1003" or prefixed "AM-1003") to the bare number; (2) a tracks persisted Claude session (track_sessions, keyed only by track number with no lane/action awareness) was never invalidated on a lane change, so re-queuing an already-done track back to plan let the worker --resume a session whose entire conversational memory was "I already finished this," round-tripping QUEUE to RUN to done in seconds with zero real work done - fixed in 47fa2c59 by invalidating the session via DELETE /track/:num/session whenever lane actually changes. Both fixes were verified only via live manual testing against real livingwork tracks and one throwaway scratch-directory test this session, never committed as an automated test. Only the "plan" alias was exercised live; the generic "lc move <id> <lane>:<status>" invocation form and the other lane aliases (implement, review, quality-gate, backlog, done, rerun) were never directly tested at all, live or automated - they share the same code path so are very likely fine, but that is an assumption, not a verified fact. Needed: a real node --test suite (matching the project established isolated-worker.mjs / mock-collector.mjs patterns, not a throwaway scratch script) covering at minimum: a prefixed INITIALS-NNN-slug folder resolves correctly for both bare-number and prefixed-identifier invocations; a lane change via lc plan/move actually invalidates a pre-existing track_sessions row (mock collector asserting the DELETE /track/:num/session call fires with the right track number); a same-lane pulse/status-only change does NOT invalidate the session; and the generic lc move <id> <lane>:<status> form and at least one non-plan alias (e.g. lc implement <id>) are exercised directly, not just plan.
