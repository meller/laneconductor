# Spec: LAN-107 — `user-stories.md` scaffold artifact + fix orphaned context docs

## Problem Statement

Downstream projects have no canonical place to record user stories/personas that an E2E testing
effort (or anyone else) can build on — they either don't exist at all, or get re-derived ad hoc
each time someone needs them. LaneConductor already has a pattern for durable, cross-track project
context (`product.md`, `tech-stack.md`, etc.); user stories belong in that same system rather than
living as a one-off file outside it.

Investigation (see index.md) found `kpis.md`/`deployment-stack.md`/`design-language.md` are
generated on disk but never synced to the DB or shown in the UI — an existing gap, not just a
precedent to copy. This track closes that gap for all four docs together.

## Requirements

### Phase 1: `user-stories.md` content shape + generation

- REQ-1: Add `conductor/user-stories.md` to the scaffold file list generated by both
  `/laneconductor setup scaffold generate` (existing-code path, reads `brainstorm_summary`) and
  `setup scaffold` Mode A/B (inferred from README/questionnaire answers).
- REQ-2: Template (stub if unknown, like `design-language.md`'s pattern):
  ```markdown
  # User Stories

  ## <Persona A> — <short journey name>
  **As a** <persona>, **I want to** <action>, **so that** <outcome>.

  Flow: <ordered list of concrete steps — screens, emails, links, endpoints touched>
  Related tracks: <[[track-name]] links, filled in as tracks implement/test pieces of this>

  ## <Persona B> — <short journey name>
  ...
  ```
- REQ-3: Not prescriptive beyond persona + journey + step list — different projects have very
  different numbers/kinds of user journeys; forcing a rigid schema would fight real usage.
- REQ-4: If `brainstorm_summary` (existing-code scaffold path) contains journey/flow language,
  seed initial content from it; otherwise stub with `<!-- TODO: describe your key user journeys -->`.

### Phase 2: Sync fix (closes the orphaned-docs gap)

- REQ-5: `laneconductor.sync.mjs`'s conductor-files builder (~line 1378) adds
  `user_stories: readIfExists(\`${dir}/user-stories.md\`)`, plus the same for `kpis.md` →
  `kpis`, `deployment-stack.md` → `deployment_stack`, `design-language.md` → `design_language`
  (matching the existing four keys' exact pattern — no new abstraction needed).
- REQ-6: Confirm the `conductor_files` JSON column write path (wherever the builder's result gets
  persisted — same code path as `product`/`tech_stack`) picks up the four new keys without a
  schema migration (it's a JSON blob column, so this should be additive-only).

### Phase 3: UI fix

- REQ-7: `ConductorPanel.jsx`'s `TABS` array gains `{ key: 'user_stories', label: 'User Stories' }`,
  `{ key: 'kpis', label: 'KPIs' }`, `{ key: 'deployment_stack', label: 'Deployment' }`,
  `{ key: 'design_language', label: 'Design' }`.
- REQ-8: `MarkdownRenderer` (already used for the other tabs) renders these with no special-casing
  needed — confirm this holds for `user-stories.md`'s persona/journey format (plain markdown,
  should Just Work).

### Phase 4: Verify

- REQ-9: Run `/laneconductor setup scaffold generate` (or `setup scaffold`) against a test project,
  confirm `conductor/user-stories.md` is created.
- REQ-10: Confirm the sync worker picks up the new file and the DB's `conductor_files` blob
  contains all four new keys within one sync cycle.
- REQ-11: Confirm the dashboard UI shows all four new tabs with correct rendered content, and that
  editing any of the four files on disk updates the corresponding tab within the existing
  `conductor:updated` WebSocket refresh path (same live-update mechanism the other tabs already use).

## Acceptance Criteria

- [ ] `user-stories.md` generated by both scaffold paths (existing-code and new-project).
- [ ] `kpis.md`/`deployment-stack.md`/`design-language.md`/`user-stories.md` all sync into
      `conductor_files` and render as dashboard tabs.
- [ ] Editing any of the four files on disk live-updates its tab via the existing WebSocket path.
- [ ] No regression to the four already-working tabs (`product`, `tech_stack`, `workflow`,
      `product_guidelines`, `quality_gate`).
