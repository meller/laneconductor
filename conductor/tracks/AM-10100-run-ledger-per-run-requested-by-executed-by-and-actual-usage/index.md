**Problem**: Execution order 2 of 5. North star: one codebase, three deployment profiles -- standalone (worker + hub-capable), hub (org management, worker-less), federated hubs (private-tracker worker sharing). Sovereign, vendor-agnostic, customer-owned. Vendor-hosted multi-tenant (TU-10048) is v3/later. -- Small, independent, ships single-node, starts collecting data on this install immediately; every org-management view in the hub track is a query over it. Two identities per lane-action run: requested_by (whose work it is -- demand side) and executed_by (whose worker/seat/machine burned the quota -- supply side). Sum by requester = each employee real required usage; sum by executor = each seat actual consumption; the gap is the picture: net contributors vs consumers, chronically capped vs idle seats, cross-team subsidy, cost per track/project. Credential- and ToS-neutral: accounting only; pooling policy sits on top separately. Already in the schema: tracks.created_by/created_by_uid/assignee_uid and the Created By / Author markers (requester); claimed_by machine_token written at claim-queue plus workers.user_uid/hostname (executor); the Last Run cli/model marker; run markers in conductor/.runs/; Session turn comments in conversation.md. Missing: (1) a runs table, one row per lane-action execution: track, lane/action, requested_by, executed_by (worker -> owner, machine, provider), model, started/ended, outcome. (2) actual usage per run: the worker already captures claude -p --output-format stream-json; the final result event carries total_cost_usd, duration_ms and token usage -- parse and store it; normalize per CLI (antigravity/copilot report differently). (3) requester rule for autonomous chains: default requested_by = assignee ?? creator; any explicit human action (card move, Re-run Implement, lc move, manager dispatch) overrides for that run; capture at queue time when the actor is known (req.user under auth, git identity / Created By otherwise). Then cost-per-track and per-seat/per-employee rollups as API endpoints and a first view on the Workers page.
