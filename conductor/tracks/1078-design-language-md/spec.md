# Spec: Add conductor/design-language.md to project scaffolding

## Problem Statement

Scaffolded projects generate `tech-stack.md`, `product.md`, `workflow.md`,
`product-guidelines.md`, `deployment-stack.md`, and `kpis.md`, but nothing dedicated to the
concrete visual design language (color tokens, typography scale, spacing system, component
conventions, light/dark variants). Maintaining a standalone design-system doc has become
common industry practice. Today it's only thinly represented as a 4-bullet "UI Aesthetic"
subsection buried inside `product-guidelines.md`, which is really about positioning/brand/UX
principles, not concrete design tokens.

Separately: `/laneconductor implement`'s "Read existing context" step (SKILL.md ~L1112-1119)
currently reads `plan.md`, `spec.md`, `deployment-stack.md`, `test.md`, `conversation.md`,
`last_run.log` — **none** of `product-guidelines.md`, `tech-stack.md`, or the new
`design-language.md`. Only `/laneconductor review` (~L1167) reads `product-guidelines.md`
today. This means UI/architecture-diverging work isn't checked against project fundamentals
until review — after the code is already written — instead of guiding the work as it's
written.

There's also no existing mechanism for `plan`/`implement` to flag when a track's requirements
conflict with, or imply a needed change to, one of these fundamental docs. Without a guardrail,
an AI agent could silently drift the project's design system, stack, or guidelines mid-track
with no visibility for a human to catch it.

## Requirements

- REQ-1: Add `conductor/design-language.md` to the files generated by
  `/laneconductor setup scaffold generate` and `/laneconductor setup scaffold` (both the
  file-generation list and Mode A's existing-code inference list). Template covers: Color
  Tokens (light/dark), Typography Scale, Spacing System, Component Conventions,
  Iconography/Motion.
- REQ-2: Add `design-language.md` to SKILL.md's "Both modes create" file tree.
- REQ-3: Add a `📝 Writing conductor/design-language.md... ✅` line to the progress-print block.
- REQ-4: `/laneconductor review`'s "Load Context" step reads `design-language.md` alongside
  `product-guidelines.md` (both `if present`).
- REQ-5 (human-confirmed): `/laneconductor implement`'s "Read existing context" step reads
  `product-guidelines.md`, `design-language.md`, AND `tech-stack.md` — all three, currently
  reads none of them — mirroring the existing `(if present)` pattern already used for
  `deployment-stack.md` at that same step.
- REQ-6 (human-confirmed): guardrail on both `/laneconductor plan` and
  `/laneconductor implement` — if a track's work implies a needed change to a fundamental doc
  (`product-guidelines.md`, `design-language.md`, `tech-stack.md`, `workflow.md`), the AI must
  NOT silently rewrite or let the track's work drift from that doc. It must post a `⚠️`-prefixed
  comment to `conversation.md` naming the specific conflict and which doc it touches. Default
  to **non-blocking** (the track continues; a human reviews and decides whether to update the
  fundamental doc or adjust the track) — matches how other automated checks in this skill flag
  rather than hard-block, reserving hard blocks for KPI-miss-style gates.
- REQ-7: No forced backfill — existing projects without `design-language.md` are unaffected;
  every read site treats it as `(if present)`, exactly like `deployment-stack.md` already is.

## Acceptance Criteria

- [ ] `design-language.md` appears in: the `setup scaffold generate` file list, its
      progress-print block, `setup scaffold` Mode A's inference list, and the "Both modes
      create" file tree.
- [ ] A `design-language.md` template block exists in SKILL.md, in the same style as the
      existing `kpis.md` template.
- [ ] `/laneconductor implement`'s context-loading step reads `product-guidelines.md`,
      `design-language.md`, and `tech-stack.md` (all `if present`).
- [ ] `/laneconductor review`'s context-loading step reads `design-language.md` alongside the
      existing `product-guidelines.md` read.
- [ ] Both `/laneconductor plan` and `/laneconductor implement` document the
      fundamentals-conflict guardrail, including the exact comment format.
- [ ] No other SKILL.md section that enumerates "the scaffold file set" is left inconsistent
      (spot-checked, not necessarily edited if the omission is reasonable, e.g. shorthand
      "etc." references).

## Data Model Changes

None — filesystem/skill-documentation only, no DB schema changes, no `.laneconductor.json`
shape changes.
