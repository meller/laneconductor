**Problem**: Many e2e test files spawn the real laneconductor.sync.mjs worker with cwd pointed at a plain, ungitted subdirectory nested inside the repo (e.g. join(ROOT, ".test-tmp-...")) instead of a real, independent sandbox repo. When such a test is invoked from inside a tracks own linked worktree (not the primary checkout) - exactly what happens when an implement/quality-gate session runs its own test suite from .worktrees/NNN - the spawned workers own REQ-1 startup cwd-normalization (conductor/laneconductor.sync.mjs, resolvePrimaryCwdDecision/resolvePrimaryRepoRoot, conductor/services/primary-cwd.mjs and conductor/services/worktree-merge.mjs) detects the ungitted sandbox sitting inside a linked worktree and resolves the primary checkout as a DIFFERENT physical directory, then process.chdir()s the worker straight into it before reading/writing conductor/workflow.json. Every subsequent relative-path read/write in that worker process now targets the real, shared primary checkout instead of the sandbox - confirmed live this session: the primary repos own conductor/workflow.json (5 real lanes: plan/implement/review/quality-gate/done) was found overwritten with a mock single-lane test fixture, breaking every lane transition project-wide until restored via git checkout. Fixed this session: conductor/tests/track-1084-worker-identity.test.mjs, whose three sandboxes (TMP, TMP_CLI, TMP_P3) all had this exact shape - fixed by giving each its own git init, matching the precedent Track 10045 already established in conductor/tests/helpers/isolated-worker.mjs (makeSandbox creates the sandbox via mkdtempSync OUTSIDE the repo entirely and git-inits it, so resolvePrimaryRepoRoot structurally cannot redirect it anywhere), which conductor/tests/local-fs-e2e.test.mjs and conductor/tests/local-api-e2e.test.mjs already migrated to for exactly this reason (see conductor/tracks/AM-10045-e2e-tests-leak-real-worker-from-worktree/spec.md). A repo-wide audit this session found 25 more test files spawning the real worker or bin/lc.mjs against a comparable ungitted, repo-nested sandbox with neither a git init nor the LC_SKIP_CWD_NORMALIZATION escape hatch nor the isolated-worker helper: conductor/tests/chat-reply-conversation-md.test.mjs, conductor/tests/track-10011-gemini-discovery.test.mjs, conductor/tests/track-10017-auto-run-phase7-e2e.test.mjs, conductor/tests/track-10020-resumed-session-unanswered-tail.test.mjs, conductor/tests/track-10035-direct-merge-e2e.test.mjs, conductor/tests/track-10035-pr-flow-e2e.test.mjs, conductor/tests/track-10047-bounded-resume.test.mjs, conductor/tests/track-10049-e2e-real-launch.test.mjs, conductor/tests/track-1085-dispatch-worker.test.mjs, conductor/tests/track-1086-session-resilience-worker.test.mjs, conductor/tests/track-1086-session-worker.test.mjs, conductor/tests/track-1087-non-claude-fallback.test.mjs, conductor/tests/track-1087-worker-chat-dispatch.test.mjs, conductor/tests/track-1089-provision-worker-dispatch.test.mjs, conductor/tests/track-1091-manager-worker.test.mjs, conductor/tests/track-1091-orphan-worker-reaping.test.mjs, conductor/tests/track-1110-lc-start-lock.test.mjs, conductor/tests/track-1110-stop-confirms-death.test.mjs, conductor/tests/track-1111-model-precedence.test.mjs, conductor/tests/track-1113-chat-coordination.test.mjs, conductor/tests/track-1119-phase6-e2e-autorun.test.mjs, conductor/tests/track-1119-wizard-dispatch.test.mjs, conductor/tests/track-AM-1121-marketing-tracks.test.mjs, conductor/tests/worker-id-watchdog.test.mjs, conductor/tests/worker-mode.test.mjs. Each needs the same treatment: migrate to helpers/isolated-worker.mjs makeSandbox/startIsolatedWorker (preferred, matches the established precedent) or at minimum add a git init -q to its sandbox directory before spawning the real worker/CLI against it. Do not just add a gitignore entry or a comment - this must actually stop the sandbox from resolving into the primary checkout.
