# Spec: Board page follow-ups (AM-10151)

Moved from track 10115 on 2026-11-19 (its plan tasks Phase 2 task 8, Phase 3 tasks 1 to 3, Phase 5 tasks 5 to 7).

## Requirements

- REQ-1 Verify, in the Claude desktop app with the parallel add-on running, that the board page reaches the connector as the host server `host:plugin_laneconductor-parallel_lc`: the Move menu changes a track's lane through `update_track` with a confirm step and shows a CONFLICT clearly, and "Check now" compares the board's commit with the repository. If the server string is wrong, fix it; if the page cannot reach the connector at all, remove the controls instead of leaving them.
- REQ-2 Look at the board by hand at 375 px width and in the light and dark themes: the Project drawer, the What's next panel, the freshness chip, the Move menu and the new "newer board" button.
- REQ-3 The Review-the-plan button in a track's detail view (the `sample` capability): a fixed instruction, the plan and spec text only when the privacy scan did not withhold them, a note that it is a separate Claude call that changes nothing; hidden when consent is not granted. Build it only if the owner wants it.
- REQ-4 By hand, on a scratch repository: `/laneconductor:status`, `:plan` and `:run`; confirm the subagent recommendation and that nothing starts unasked.

- REQ-5 The board add-on's Stop hook notices a change of the tracks by any tool, not only Edit and Write (owner, 2026-11-20: "was expecting the hook to work"): it compares a fingerprint of the tracks (the tree of `conductor/tracks` on the state branch, plus the uncommitted changes under it) with the one seen at its last prompt, so a Bash edit, a scratch worktree, another session or a push marks the board stale. The first Stop only records the fingerprint; `board.auto_update: false` and a missing board stay silent; the only child process is a read-only `git` (rev-parse, status). Built as board 1.10.4.
- REQ-6 In a track's drawer, each track it depends on or waits on is a button that opens that track ("Blocked by", and "Needs (done)" for finished ones). Built in board 1.10.3.
- REQ-7 A track's KPI (`**Serves**`, or a `KPI Check After`) is a button that opens the KPIs tab of the Project drawer, and a Discuss button next to Copy copies a prompt that asks Claude to read the track and talk it through without running a lane or changing a file. Built in board 1.10.3.

- REQ-8 A refresh that was just made is not asked for again (owner, 2026-11-20: the hook asked for a refresh I had already published). The hook script has a `seen` step that records the tracks' current state as the one the board shows and clears the marker; the refresh command runs it last, after a successful publish. A run from a shell without `CLAUDE_PLUGIN_DATA` writes to the temp fallback, and the hook reads both places, newest record wins. Built as board 1.10.8. The base command `/laneconductor:board refresh` does not run it (the base never names the add-on's files), so the hook may ask once more after that command.

- REQ-9 The board shows a lane as running when it starts (owner, 2026-11-20: a plan run in Otralingo did not show running; the first Stop came after the plan was done). The hook's tool-call check notices a track set to running in plan, implement, review or quality-gate (an Edit or Write of its index.md, or an update_track setting both markers), once per claim, and asks Claude to run the refresh right then and carry on. Never from a sub-agent (it cannot publish), and not when `board.auto_update` is false or no board is stored. The refresh asked for by the hook, at a lane start or at the end of a turn, is quiet: it reports nothing, not the link, the counts or the withheld files, unless a step failed (owner: the report distracts from what the person was doing). Built as board 1.10.9.

- REQ-10 Everything is typed under `/laneconductor:` (owner, 2026-11-20: no `laneconductor-board:` commands). The partial-publish refresh moved into the base command `/laneconductor:board refresh` (read the live manifest and board, `--previous` and `--live-board`, send only what `publish` lists, then the hook script's `seen` step found by Glob); the board add-on ships no commands; the hook asks for `/laneconductor:board refresh`. Built as base 1.9.14 (and parallel 1.9.14) with board 1.10.10. The old `/laneconductor-board:refresh` is gone.

- REQ-11 A project finds its own board (owner, 2026-11-21: the Coach AI project could not tell which of six boards named "LaneConductor Board" was its own, asked which one, and when skipped created a second board for the same project). With no stored `board.artifact_url`, the base `board` command lists the artifacts, reads the `board.json` of each board and matches its `project` with this project's name; one match is adopted and its URL stored; several: the most recent is used and the others named; none: create. It never asks which one. The settings file is read from the main checkout when a git worktree has no copy of it (the board hook does the same). A board is named after its project: the page `<title>` is "<project> Board" (the project name is cleaned and clipped to 40 characters), so the artifact list is readable. Built as base 1.9.15 and board 1.10.11; an existing board takes the new title at its next refresh. Cleanup done the same day: the duplicate board of that project was deleted and its settings point at the remaining one.

## Out of scope

The board add-on's refresh and hooks (done in 10115); the extra hooks of 10115 Phase 1 (not built, reopen as a new track if wanted).
